# D-007B — Escalas e 12x36 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** adicionar planejamento de jornada com escalas fixas e cíclicas 12x36, associações por usuário, exceções auditáveis, vínculo planejado com a sessão realizada e visão de cobertura, sem ainda integrar elegibilidade ao despacho.

**Architecture:** D-007B cria um domínio separado de planejamento (`work_shift_schedules`, `work_shift_assignments`, `work_shift_schedule_exceptions`) e um avaliador puro que resolve a janela planejada para um usuário em um instante. O serviço de sessão da D-007A passa apenas a capturar o planejamento resolvido no início da jornada; a D-007C continuará responsável por filtrar candidatos de despacho. Toda persistência nova permanece atrás de portas testáveis e procedures tRPC finas.

**Tech Stack:** TypeScript 5.9, Node 24, Express/tRPC 11, Drizzle ORM 0.45 + MySQL, Zod 4, Vitest 2, pnpm 10.4.1.

**Spec:** `docs/superpowers/specs/2026-09-04-d007-controle-jornada-design.md`

## Global Constraints

- Base funcional: `checkpoint/d007a-work-shift-history-20260904`.
- Preservar integralmente D-007A: `work_shift_sessions`, `work_shift_events`, `teams.*shift*`, `teams.updateShift` e contratos `workShifts.*` existentes.
- Não implementar D-007C: nenhum filtro de candidato, nenhuma chamada ao GIS/OSRM e nenhuma alteração no ranking de despacho.
- Não implementar D-007D: nenhum fluxo de aprovação de ajustes, relatórios administrativos completos ou alertas automáticos.
- 12x36 deve usar `cycleAnchorAt`, timezone explícito, 12 h de trabalho e 36 h de descanso; não inferir apenas por alternância de datas.
- Associações ativas e temporalmente sobrepostas para o mesmo usuário devem ser rejeitadas.
- Exceções têm precedência sobre a regra recorrente da escala.
- O servidor define os instantes autoritativos; inputs administrativos aceitam períodos planejados, mas sessão real continua usando horário do servidor.
- Novas permissões entram apenas no catálogo: `work_shift_schedules.view` e `work_shift_schedules.manage`; não criar grants automáticos em `role_permissions`.
- Wildcard administrativo legado `*` permanece compatível.
- Nenhuma migration será aplicada em banco real; não executar `pnpm db:push` nem `drizzle-kit migrate`.
- Cada task segue RED → GREEN → regressão → commit pequeno.
- Gates finais: `security:check`, `check`, `test`, `build`, GIS visual homologation, NEO external compatibility e NEO workspace visual homologation.
