# CP-016 MySQL CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Executar migrations e testes de jornada em MySQL descartável no GitHub Actions.

**Architecture:** Workflow limitado à branch CP-016, token somente leitura e serviço MySQL 8.4. Credenciais de teste literais sem uso de secrets. Testes usam o helper real `adjustWorkSession` e consultam o banco após commit ou erro.

**Tech Stack:** GitHub Actions, MySQL 8.4, Drizzle, Vitest, Node 24, pnpm.

**Spec:** `docs/governance/CP016-revisao-2026-09-05.md`; autorização nesta conversa para CI com banco descartável.

## Global Constraints

- Sem produção, merge, deploy, alteração de main ou versão 1.15.5.
- Publicação de infraestrutura diagnóstica autorizada; não equivale à aprovação do CP-016.
- Sem `pull_request_target`, secrets, permissões de escrita ou migrations geradas automaticamente.

## Task 1: Testes reais e infraestrutura

**Files:** Create `server/workSessions.integration.test.ts` and `.github/workflows/cp016-mysql-integration.yml`.

**Interfaces:** Consome `adjustWorkSession`, `setDbForTesting`, tabelas de jornada/auditoria e migrations versionadas. Produz evidência de persistência e rollback.

- [ ] Criar teste de ajuste: início 08:00 vira 09:00 UTC, pausa 120 segundos, evento adjustment e auditoria com antes/depois.
- [ ] Criar teste de motivo vazio: promessa rejeitada e sessão inalterada, sem evento/auditoria.
- [ ] Criar teste de falha de auditoria: trigger restrito ao usuário da fixture rejeita INSERT; sessão permanece original e evento é revertido. Remover apenas o trigger e registros criados pela suíte.
- [ ] Validar destino: flag CP016_DISPOSABLE_DB=1, host 127.0.0.1 e banco dispatch_cp016_ci; falhar antes de conectar se diferente.
- [ ] Criar workflow push apenas feature/cp016-operational-data-model, MySQL com healthcheck, timeout e token contents:read. Executar `pnpm check`, `drizzle-kit migrate`, teste bootstrap e demais testes integrados em etapas sequenciais.
- [ ] Executar `pnpm check` localmente e analisar YAML. Publicar somente os arquivos novos na branch autorizada, sem sobrescrever histórico divergente.
- [ ] Ler o CI do SHA final: distinguir falha de infraestrutura, migration ou asserção. Não declarar sucesso sem execução real. Regressões unitárias continuam no CI CP-016 existente.

## Limites

Estes testes caracterizam comportamento existente; não introduzem correção funcional nem comprovam elegibilidade, concorrência de presença ou homologação operacional completa. A impossibilidade de executar MySQL localmente permanece explícita.
